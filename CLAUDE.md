# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

An R pipeline that predicts next-season NFL fantasy football points, blends those predictions with FantasyPros expert projections, and produces tiered draft rankings. There is no build system, linter, or test framework — scripts are run interactively in RStudio (`ff.Rproj`).

## Critical: How Scripts Are Run

**Do NOT run these scripts end-to-end with `Rscript`.** Per the warning at the top of `01_build_nfl_model.R`, scripts are intended to be evaluated in steps (interactively) so data quality and model behavior can be inspected along the way. Model training runs Bayesian hyperparameter optimization that takes a long time.

## Pipeline Architecture

Scripts run in numbered order, passing data between stages via CSVs in `data/` (gitignored — files exist locally only):

1. **`00_globals.R`** — sourced by every other script. Installs/loads packages and defines globals: `EVAL_YEAR` (final training year), `PRED_YEAR` (= EVAL_YEAR + 1), `START_YEAR` (2006 — aligns with start of ESPN QBR coverage), `SCORING_TYPE` ("PPR"/"HALF"/"STANDARD"), `PPR_MULT`. Note `chromote` is in `required_packages` for the FantasyPros scrape in `02` — it drives a real **Google Chrome** install, the pipeline's one non-R dependency. On a machine without Chrome the scrape fails and `02` falls back to the manual CSV exports.

2. **`01_build_nfl_model.R`** — sources `functions.R` for data intake. Player data comes from **nflreadr/nflverse** (the legacy PFR scraper is retired — PFR blocks scraping): `build_player_season_stats()` pulls season-level player stats, rosters (age/draft capital/ESPN-id crosswalk via `load_ff_playerids`), ESPN QBR, and team wins from schedules, writing one cached table at `data/player_stats_final_{START_YEAR}_{EVAL_YEAR}.csv` — the path is **versioned by year range** (`stats_path`), so bumping `EVAL_YEAR` creates a new cache rather than overwriting the old one — keyed by **GSIS `player_id`** and controlled by `SKIP_DATA_LOAD`. Note `data/player_stats_final.csv` (unversioned) is a **dead legacy file**: nothing reads or writes it, which is why it is frozen at 2006–2007 and missing the raw EPA columns. Ignore it; it is not what `SKIP_DATA_LOAD <- TRUE` loads. Substitutions for columns PFR had but nflverse lacks are documented in the `build_player_season_stats` docblock (success rates → EPA-per-play; longs → air yards/YAC; awards → draft capital; QB record → team wins; GS/4QC/GWD dropped). `build_player_season_stats` also carries nflverse **opportunity-share / efficiency** columns through `transmute`: `target_share`/`air_yards_share`/`wopr`/`racr` (receiving) and `passing_cpoe`/`pacr`/`passing_adot` (QB; `passing_adot = passing_air_yards / attempts` is depth of target — the one passing metric that isolates air yards from YAC). ESPN QBR only exists for *qualified* QBs — backups get zero by design. The script then builds the `combined` dataset with fantasy points and ~80 engineered features (lags, 3-yr rolling averages of the above shares/efficiency stats included, career cumulatives, age interactions, injury flags, `draft_capital` — an exponential-by-pick draft value that decays 25%/league-year to 0 after 4 years, replacing raw `draft_number` so pedigree stops influencing veteran predictions — and a set of concept-driven composites: TD-regression rates (`receiving_td_rate`/`rushing_td_rate`, TDs per yard to flag unsustainable scoring), role-trend momentum (`target_share_delta`/`wopr_trend`), realized consistency (`points_cv_3yr`) and trajectory (`points_trend_3yr`, a trailing OLS slope), and `youth_opportunity` (`wopr / Age`); helpers `coef_var` and `trailing_slope` back the rolling composites; plus year-over-year momentum deltas and usage-vs-baseline gaps — `avg_points_per_game_delta` (rate delta, all positions), `touches_delta` (RB), `pass_att_per_game_delta` (QB), `yards_from_scrimmage_delta` (RB/WR), and `wopr_vs_3yr`/`target_share_vs_3yr` (WR/RB opportunity minus its trailing 3yr average — the usage analog of `points_vs_3yr_avg`, flagging anomalous seasons that mean-revert). Rate deltas isolate a genuine role change from games missed, unlike the raw `points_delta`; plus position-specific **efficiency-trajectory trends** — trailing 3yr OLS slopes (via `trailing_slope`) of a stable efficiency metric to capture athletic gain/decline: `passing_adj_net_yards_att_trend_3yr` (QB ANY/A), `rush_epa_per_att_trend_3yr` (RB rushing), `receiving_yards_target_trend_3yr` (WR/TE yards per target) — each the *direction* complement to the metric's existing `_3yr` *level* average), and trains **three position-specific XGBoost models** (`train_position_model`) with Bayesian optimization. Position grouping: QB alone; RB includes FB; **the "WR" model includes TEs**. `train_position_model` takes a `random_state` (the `RANDOM_STATE` config knob) threaded through the split, baseline, tuning, and final fit — change it to generate alternate draft scenarios. After training, `generate_prediction_intervals` **simulates possible player outcomes** and turns them into bands. It runs a player-level (cluster) bootstrap — reusing each model's tuned hyperparameters **and CV-chosen tree count** (fixed `nrounds`, no early stopping), where the spread of refit predictions is the *epistemic* uncertainty and pooled out-of-bag residuals, **binned by fitted value** (heteroscedastic) from one global pool, are the *aleatoric* noise. That mixture is evaluated **exactly rather than sampled**: each residual pool is discretized onto an equal-weight quantile grid (`n_grid`, default 2000) and the reported percentiles are quantiles of the full `n_bootstrap × n_grid` cross-product, so the band edges are **deterministic given the refits** and carry no Monte Carlo error. The distribution is still a simulation and remains inspectable — `attr(result, "simulate_draws")` emits draws on demand for functionals the stored percentiles can't answer (P(top-12 finish), P(bust below X)). This replaced a 30×50 = 1500-draw sampler whose sampling error in `p95` was **as large as the entire cross-player spread `ceiling_index` standardizes** (MC sd ≈ 0.056 × level vs a detrended signal sd of 0.054 QB / 0.078 RB / 0.074 WR), and which called `set.seed` *outside* the per-player loop so two identical players got different ceilings. It produces `Floor`/`Ceiling` (p05/p95), the full percentile set, and three **level-normalized upside signals** via `add_upside_indices` (split out so any band-producing path computes the indices identically — it must be called **per model group**, since each index is standardized within the frame passed in). `pred_mean` is *exactly* `Predicted`; note `pred_p50` sits ~15% below it (`Predicted` lands at the ~56th percentile of its own band) because the outcome law is right-skewed and the point model predicts a conditional **mean** — a real mean-vs-median gap, not a centering bug.

**Per-player outcome shape (`train_shape_models`).** The 10-bin residual pooling is **gone**, replaced by a global empirical *shape* stretched per player by his own learned half-widths. Why: binning sized outcome noise by projection decile, so every player in a decile shared one pool and only the bootstrap's **symmetric** refit spread distinguished them — which made `Ceiling / Predicted` and `Floor / Predicted` one axis with opposite signs (each correlating +0.63…+0.86 and −0.51…−0.78 with the same detrended band width) and collapsed `upside_index` into "whose band is an unusual width". `train_shape_models` fits `reg:quantileerror` at 0.05/0.50/0.95 per position (reusing the point model's tuned params, `nrounds` re-chosen per alpha; `quantile_alpha` **must** go inside `params` or xgboost silently ignores it) and supplies `d_lo`/`d_hi`. They are **never reported** — `Floor`/`Ceiling` still come out of the simulation; the models only set how far it reaches down versus up. Trained on the **untruncated** `combined_train`, not `model_df`, whose `points_next_year` threshold is a filter on the *outcome* and deletes exactly the bust seasons a floor must represent.

**`Predicted` is now the MEDIAN of the simulated law, not its mean.** The per-player grid is anchored on its median, and this is load-bearing: the *mean* of an asymmetrically-stretched grid depends on **both** half-widths, and since `d_hi` runs 3–4× larger than `d_lo`, mean-anchoring let a large `d_hi` drag the floor down too and re-coupled the very edges the shape models decouple (measured: `cor(ceiling_index, floor_index)` −0.351/−0.450/−0.549 mean-anchored vs **−0.044/+0.042/−0.225** median-anchored). This also retires the old oddity where `Predicted` sat at the ~56th percentile of its own band. `epi_weight` scales the symmetric refit spread (measured: 1 vs 0 changes the indices almost not at all). **Do not remove the bootstrap on that basis** — it is one of the two seed-varying components, and seed-to-seed band movement is *wanted* here (see below); it is also the source of the OOB residual pool `unit_shape()` needs, so removing it would require k-fold out-of-fold residuals as a replacement.

**Seed-to-seed variation is a FEATURE, not a defect.** A different `RANDOM_STATE` refits the bootstrap and the shape models, giving a genuinely different fitted view of a player — which is used deliberately for **player-exposure hedging** across alternate draft scenarios. Two kinds of randomness must be kept distinct: *within-run draw noise* (two identical players getting different ceilings in one run because `sample()` differed) reflected no view of anybody and was correctly removed by evaluating the mixture exactly; *across-run model variation* is the useful kind and is deliberately preserved. So `noise_ratio` in `tests/interval_stability_check.R` is **reported, not minimized** — read it beside Spearman, where high Spearman with substantial `noise_ratio` is healthy (same read, jittered) and Spearman near 0 is the real problem (arbitrary ordering rather than a second opinion). Determinism at a *fixed* seed must still hold, for reproducibility.

**Verified after the change** (real data, saved tuned params): level-neutrality of `upside_index` 0.014/0.006/0.039 (was 0.305/0.302/−0.073); no tie mass (all values distinct, was 17–24% sharing the exact minimum); no discretization stepping; QB top-decile driver mix 44% both / 56% volatile (was 89% volatile, 0% floor-involving); face validity restored (top 12 spans projections 42–200 and includes McCaffrey/Murray/Kamara, replacing a run of six near-identical fringe TEs).

**BACKTEST RESULTS (holdout 2024 → realized 2025) — read the draft-pool numbers, not the pooled ones.** Restricted to a realistic pool (QB24/RB48/WR60/TE24, n=156) the bands are **well calibrated**: `cover_80` 0.782, `below_floor` 0.115, `above_ceiling` 0.103 against nominals of 0.80/0.10/0.10. Across *all* 588 players with a game played the same bands look terrible (`cover_80` 0.463, `below_floor` 0.507) — but that is driven by fringe players where **the point model over-predicts 2–6×** (`med_actual_over_pred` 0.09–0.72 in the low quintiles) because `model_df` is truncated on the outcome. That is a **level** error in `Predicted`, predates this work, and no band centered on a wrong number can fix it. `03` trims to positional cutoffs, so the board only ever sees the calibrated population.

**Index validation — pooled over four holdout years (2021–2024), draft pool only, n=624.**

`floor_index` is **weak but directionally consistent**, which is what makes it credible. Across its quartiles: bad misses (`actual < 0.5 × Predicted`) fall 0.237 → 0.154 → 0.167 → **0.135**, and out-of-league falls monotonically 0.064 → 0.026 → 0.013 → **0.013**. Spearman vs `actual/Predicted` +0.068 (p=0.092) — not significant alone, but three independent risk measures agree on direction.

`ceiling_index` shows **no detectable signal**: Spearman −0.018 (p=0.646), and the direction *flips by threshold* — `hit_1.5x` is 0.109/0.103/0.109/**0.154** (Q4 best) while `hit_1.25x` is 0.301/0.237/0.295/**0.231** (Q4 worst). Inconsistent sign is the signature of noise rather than a small real effect.

**But the test is badly underpowered, so this is not evidence of absence.** At a base `hit_1.5x` rate of 0.119 and n=156 per quartile, power to detect a 1.25× lift is **0.12**, a 1.5× lift **0.31**, and only a 2× lift reaches 0.78. Anything under a doubling is invisible here. Treat `ceiling_index` as **unproven, not dead**.

**`upside_index` is a deficit-weighted SUM of the two axes, on a tail-equalized scale.** Surpluses above 100 count in full, deficits count at `UPSIDE_DEFICIT_WEIGHT` (0.40), and the weaker axis earns `UPSIDE_BOTH_BONUS` (0.25) extra once it too clears 100.

This replaced a `pmax(ceiling_index, floor_index)`, which ignored the weaker axis entirely unless it beat 100 — **Josh Allen scored 104 on a `ceiling_index` of 20**, and Jerry Jeudy (102/86) scored 103. A plain sum (`ceiling + floor - 200`) over-corrects the other way: the axes anti-correlate in the tails, so it cancels exactly the players it should flag (Tyreek Hill 149/61 fell 170 → **107**, Malik Nabers 136/47 → **87**) and degenerates into a floor sort (Spearman 0.85 vs `floor_index` alone, 0.17 vs `ceiling_index`). Damping the deficit keeps both specialist types on the board — measured: Hill 139 and Ferguson (92/145) 136 sit side by side in the new top six.

**Tail equalization via `rank_normal_at` is why the sum is fair.** Both axes are mean-100/sd-15 but not the same *shape*: `ceiling_index` is strongly **left**-skewed (−1.82 QB / −2.16 RB / **−6.13** WR) while `floor_index` is **right**-skewed (+0.92 / +1.76 / +0.39), so `floor_index` owns the long upper tail and any sum of raw deviations silently over-weights it. Mapping each axis through its own ECDF to a normal score makes a +2sd ceiling exactly as rare as a +2sd floor (WR balance moves from 0.25/0.77 ceil/floor to **0.67/0.46**). The `qnorm(p0)` re-centering inside `rank_normal_at` is load-bearing: a plain rank-normal score puts neutral at the axis's *median*, which is not 100 on a skewed axis (only ~30% of WR `ceiling_index` values sit below 100), and that produced **7 guarantee violations** on the saved run versus **0** anchored, at Spearman 0.973–0.996 between the two forms.

**It is anchored at the NEUTRAL point, not standardized to the mean:** a player at exactly 100 on both axes scores exactly 100, so above 100 on both *always* scores above 100, below on both always scores below, and the score is monotone increasing in each axis (slope 1 above neutral, 0.40 below). The earlier `index_100(level_adjust(hypot(soft_pos(...))))` form violated this for **19% of players above 100 on both** (Tyler Warren: 102.6 / 108.0 → 94.6), because `index_100` puts 100 at the *mean* of the combination, which sits well above the neutral point. The composite is deliberately **not** level-adjusted, since `level_adjust` is a relative transform that can reorder players at different projections and would break the guarantee. **Consequence: 100 means "neutral on both axes", not "typical player" — the median player scores ~104 QB / ~104 RB / ~114 WR.** Level-neutrality is comparable-to-better than the `pmax` form (Spearman vs `Predicted`: RB −0.39 → +0.21, WR −0.27 → −0.08, QB −0.02 → +0.19), and rank agreement with it is 0.85–0.92 — a real reshuffle, not a rewrite.

**Practical guidance:** trust `Floor`/`Ceiling` as a calibrated range and `pred_upside` for raw magnitude; use `floor_index` with mild confidence for safety tie-breaks; do not tier on `ceiling_index` or `upside_index`, but there is no reason to remove them either. Resolving `ceiling_index` properly needs more holdout years or a positional-finish outcome with a higher base rate.

**Two clamps that are load-bearing.** `predict_shape` returns **relative** half-widths (each half as a fraction of the shape model's own median), scaled onto `point_pred` in `generate_prediction_intervals`. Returning raw widths mixed the untruncated shape scale (~55) with the truncated point scale (~112) and left fringe players a floor near 57 when the model correctly said zero — 64% of all players finished below their own 10th percentile, and `floor_index` came out **inverted** (bust rate climbing 0.42→0.79) because `Floor/Predicted` was largest exactly where the shape model disagreed downward with the point model. Separately, quantiles are clamped at **0** before forming ratios, and the simulated values clamped at 0 too: the regression happily predicts `q05 < 0`, which drove `r_lo` above 1 and produced negative floors (median `Floor/Predicted` of −3.46 in the lowest quartile). Note that removing negative floors made pooled `below_floor` look *worse* (0.165 → 0.507) — the earlier number was a fake pass, since a negative floor trivially "contains" an actual of 0.

**Known open issues.** (a) **WR still fails the secondary test** — band width beats skew at explaining its ceiling signal (R² 0.84 vs 0.65), though QB and RB now pass (0.83>0.82, 0.79>0.69) and all three clear the primary `cor(ceiling_index, floor_index)` target. (b) Floors moved a lot — median `Floor/Predicted` 0.67–0.71 vs 0.29–0.35 before — and **~4.9% of QB floors are now negative**, so `tests/interval_coverage_backtest.R` must confirm coverage before these bands are trusted. (c) **The deficit weight costs pure-floor players some ground** — a floor specialist has a sub-100 ceiling by definition, which is now a (damped) penalty. Draft-pool top decile is floor-driven 0.22 at WR but **0.00 at QB and RB**, and mid-tier floor specialists slide (Jordan Mason 90/136: 94th → 75th percentile; Croskey-Merritt 84/129: 88th → 67th), while the strongest cases hold (Jake Ferguson 92/145 at 98th, AJ Barner at 93rd). This is the intended trade for closing the `pmax` free pass, not a defect — but if pure-floor safety picks matter more than it allows, lower `UPSIDE_DEFICIT_WEIGHT` rather than changing the structure. (d) Seed stability after the change is unmeasured — run `tests/interval_stability_check.R` (it now needs `qb_shape`/`rb_shape`/`wr_shape` in the environment). `ceiling_index` and `floor_index` each take a band edge relative to the model's central estimate (`Ceiling / pred_mean`, `Floor / pred_mean`), then **level-adjust it against the projection** via `level_adjust()` — a studentized residual (loess within position) that equalizes *both* the average *and* the spread by level, so no projection tier is favored in the center or the tail (a raw ratio over-corrects ~−0.9; a mean-only detrend still let one tier over-populate the top ~0% vs ~41%). The scale denominator is **floored at half the typical |residual|** (`0.50 * median(abs(resid))`) because the `|residual|` smooth collapses toward zero at the sparse top of the projection range, where a player has few level-neighbours: the earlier 5% floor permitted a denominator 20× tighter than typical, which turned an ordinary −0.02 residual into a `ceiling_index` of **−12** for the #1 RB and then inflated that position's sd enough to compress everyone else toward 100. Widening the `|residual|` smooth's span instead also removes the outlier but *breaks* level-neutrality (the top projection tercile took 20% of WR top-decile slots), so the floor is the fix to keep. The studentized residual is then standardized **within position** to mean 100/sd 15: `ceiling_index` flags an unusually high ceiling *for a player's level* (boom), `floor_index` an unusually high/safe floor (safety). Being level-*relative*, these are deliberately not "biggest raw ceiling" sorts — the player with the highest absolute `Ceiling` in a position can score below 100 if that ceiling is ordinary next to his projection; `Ceiling`/`pred_upside` are the columns for raw magnitude. `upside_index` combines them as a **deficit-weighted sum over tail-equalized axes** (see the scale note above): a player is rewarded for spiking on *either* axis, earns extra for both, and pays a damped price for a weak one. Because low-projection players tend to score via ceiling and high-projection ones via floor, `upside_index` surfaces good bets across every value tier instead of tracking the projection (an earlier single upside/downside *ratio* correlated almost perfectly with predicted points and was deliberately replaced). `tests/interval_coverage_backtest.R` validates their empirical coverage. Output: `data/model_pred_{PRED_YEAR}_{SCORING_TYPE}.csv`, keyed by **GSIS `player_id`** and carrying the interval columns alongside `Predicted`.

3. **`02_combine_projections.R`** — sources `functions.R` for the FantasyPros intake and pulls draft projections via **headless Chrome against a persistent logged-in profile**, falling back per position to **manually exported CSVs**. `load_fp_projections` (in `functions.R`, called with `use_scrape = !SKIP_FP_SCRAPE`) is the dispatcher: it calls `scrape_fp_projections` (one `chromote` session for all four positions, parsing `table#data` with `parse_fp_projections_html`) and, for any position that errors or comes back below `FP_MIN_ROWS` (20), warns and reads `read_fp_projections_csv` from `data/fp_raw/{SCORING_TYPE}/FantasyPros_Fantasy_Football_Projections_{POS}.csv`. `SKIP_FP_SCRAPE <- TRUE` forces the CSV path (mirrors `SKIP_DATA_LOAD` in `01`). Three findings drive this design, all established by testing in `tests/fp_scrape_auth_test.R`: **(a)** FantasyPros has no CSV endpoint — its own download link is generated client-side by `window.exportTableToCSV` serializing the rendered DOM, so the manual exports and the scrape read the identical table (verified: median difference 0.0 across all four positions); **(b)** the fence is *server-side row truncation* to 10 players, not user-agent filtering, so the retired browser-user-agent scraper never had a chance — and a real browser gets 10 rows too when unauthenticated, with JS adding none, meaning the full table *is* server-rendered once logged in; **(c)** logging in from R is impossible — the form mints a reCAPTCHA v3 token via `grecaptcha.execute()` before posting, and a POST with an empty token is rejected as bad credentials *even when the credentials are valid*. Hence the browser profile: log in by hand **once** (`open -na "Google Chrome" --args --user-data-dir=~/.fp_chrome_profile https://secure.fantasypros.com/accounts/login/`) and Chrome persists the cookie jar in `FP_CHROME_PROFILE` (`~/.fp_chrome_profile`); no password or cookie is stored by this repo. `assert_chrome_profile_ready` guards two failure modes worth knowing: Chrome permits **one process per profile directory** (so the login window must be closed before scraping, and a stale `SingletonLock` from a crash is cleared automatically), and given a `--user-data-dir` it cannot use, Chrome **silently falls back to the user's default profile** — hence the existence check. It then joins them to model predictions on cleaned player names (`clean_player_name` strips suffixes/punctuation). FantasyPros ships **no player id**, so the expert side is name-matched, but the model side carries its **GSIS `player_id`** so same-named players (e.g. the two Adrian Petersons) stay distinct; when both match one FantasyPros row the projection attaches only to the highest-projected (active) player, and the other is dropped by the no-FantasyPros filter. Applies **manual per-player multipliers** (the big `case_when` block for injuries, depth-chart changes, etc. — updated by hand each season, and applied **only** to the model prediction, not the interval columns), then blends per position: `pred_w * model + proj_w * dampened_expert`, where `pred_w` is looked up from `PRED_WEIGHTS` (a Pos-keyed vector — QB 0.50, RB 0.40, WR/TE 0.60) and `proj_w` is its complement (`1 - pred_w`). Penalty factors apply when only an expert projection exists (rookies). The model's `Floor`/`Ceiling`/`upside_index` ride through untouched. Output: `data/blended_proj_{PRED_YEAR}_{SCORING_TYPE}.csv` (carries `player_id` + interval columns).

4. **`03_create_player_tiers.R`** — trims the player pool to platform-specific positional cutoffs (commented blocks for Underdog/DraftKings/ESPN/Yahoo — uncomment the right one), computes `Relative_Value` as a 50/50 blend of z-score value and VORP (VORP scaled ×2.25, derived in `tests/estimate_vorp_zscore_blend.R`), applies positional dampening (`QB_DAMP`, etc.), then k-means clusters into overall and per-position tiers (use the elbow plots to pick k). Tier assembly reads straight from the clustered frame (no name-based self-join). Output: `data/final_projections_{PRED_YEAR}_{SCORING_TYPE}.csv`, carrying `player_id` and the model interval columns (`Floor`/`Ceiling`/`upside_index`) through to the final sheet.

### Cross-script state dependency

`02_combine_projections.R`'s `plot_pred_vs_proj_dumbbell` (model-vs-FantasyPros dumbbell chart, top-N per position) draws its colors from `NFL_COLOR_PALETTE`, which is defined in `evaluate_model.R` (sourced by `01`) — it must be in the global environment when `02` runs (sessions are stateful; scripts are not fully self-contained). The chart itself reads only `final_df` built within `02`, so the old dependency on `01`'s `combined` dataframe is gone.

### FantasyPros login refresh (the one recurring manual step)

The scrape in `02` authenticates by reusing a **Chrome profile that is already logged in**, at
`FP_CHROME_PROFILE` (`~/.fp_chrome_profile`, outside the repo). Nothing in the repo stores a
password or a cookie.

**Symptom that it has lapsed:** `02` warns that a position returned ~10 rows (the anonymous fence),
and that position silently falls back to its manual CSV export.

**Fix** — run in a terminal, log in, then **close the window**:

```bash
open -na "Google Chrome" --args --user-data-dir=~/.fp_chrome_profile https://secure.fantasypros.com/accounts/login/
```

Closing it matters: Chrome allows one process per profile directory, so leaving the login window
open makes the next scrape fail with `SingletonLock: File exists` (surfacing through `chromote` as
the misleading "Cannot find an available port"). `assert_chrome_profile_ready` translates that into
a real message and auto-clears a *stale* lock left by a crash.

To diagnose further, run `tests/fp_scrape_auth_test.R`, which checks the anonymous baseline, the
scrape, parity against the manual exports, and the table's column layout.

`FP_COOKIE` / `FP_SESSIONID` / `FP_USERNAME` / `FP_PASSWORD` in `.Renviron` are **not used by the
pipeline** — only by the abandoned-approach blocks in that diagnostic. The pipeline needs none of
them, and they can be deleted.

### functions.R

Shared home for data intake and cleaning helpers (`clean_player_name`). Two intake groups live here: the **nflverse** functions used by `01`, and the **FantasyPros projections intake** used by `02` (bottom of the file, under its own banner) — `load_fp_projections` and its machinery, plus `read_fp_projections_csv`. The CSV reader is deliberately kept beside the scraper: it is both the automatic per-position fallback and the documented way back to hand-exported projections should the scrape stop working. Use the magrittr `%>%` pipe throughout (available via `tidyverse` in `00_globals.R`) — the native `|>` pipe was retired from this repo. The legacy PFR functions (`scrapeData`, `clean_traded_players`) remain only for the archived scripts in `tests/` — do not use them for new data pulls. `02_combine_projections.R` still redefines its own `clean_player_name`; remaining modeling/plot functions in `01` are a standing TODO to consolidate.

## `tests/` Directory

Not unit tests — these are one-off analysis/optimization scripts:
- `validate_nflreadr_migration.R` — compares the nflverse dataset against legacy PFR CSVs
- `model_proj_blend_analysis.R` — backtests blend weights against actual season results
- `estimate_vorp_zscore_blend.R` — regression analysis behind the 2.25 VORP multiplier
- `interval_coverage_backtest.R` — validates empirical coverage of the prediction intervals. **Self-contained**: reads `data/combined_features_{EVAL_YEAR}.csv` (written by `01`) and imports `01`'s function definitions without executing it, then trains its own models on a **rolled-back holdout** (`HOLDOUT_YEAR = EVAL_YEAR - 1`, scored against the realized `HOLDOUT_YEAR + 1`). Rolling back is mandatory: at `EVAL_YEAR` there are no actuals, and the previous version silently compared every band against `actual = 0` (see the `points_next_year` note under Domain Conventions) so it had never measured anything. Reports coverage **and pinball loss** (coverage alone can't tell a well-placed band from a lazily wide one), splits every row by `played_next`, and tests whether `ceiling_index` predicts realized booms
- `interval_stability_check.R` — determinism (same seed must be bit-identical) and two-seed reliability (`noise_ratio = sd(a - b) / sd(a)`) for the band edges and the three indices; consumes in-memory `*_model`/`model_df`/`*_pred_df` from `01`
- `similarity_bakeoff.R` — the gate on how the simulated outcome pool should be conditioned: projection level only (status quo) vs analogs by career **trajectory** vs analogs by XGBoost **leaf co-occurrence**, scored on pinball loss across several holdout years with `K` tuned. Self-contained like the backtest. **Result against the real tuned models** (holdouts 2022–2024, 1,773 player-seasons): analog conditioning wins **7 of 9 position-year cells**, and it splits cleanly by position — `leaf`/`traj` win **3/3 at WR** (3.94–5.03%) and **3/3 at RB** (2.38–3.94%), while **QB stays with level-only** (`global` wins 2 of 3, margins swinging +5.40%/+1.31%/−2.87%, i.e. noise). Pooled `pin_avg`: `leaf@200` 7.543 < `traj@100` 7.624 < `global` 7.774. **`leaf` beats `traj`** (5 cells to 2), consistent with leaf similarity improving with model quality. The indicated design would be **mixed conditioning**: leaf analogs for RB and WR, level-only for QB. **DECISION (2026-07-31): deferred, not built.** A 2–5% pinball gain does not justify two divergent conditioning paths plus an analog outcome table and a K sweep, particularly since `K = 200` was the best value tested *and the largest*, so the optimum is likely past the grid and the work would need redoing after testing 400. All arms also still over-cover (`cover_80` ≈0.87 vs nominal 0.80), so a width recalibration is a cheaper lever that could shift the standings on its own. Revisit only if the margins widen with more holdout years or a tuned `K` — the gate is already written, so re-running it is cheap. Note an earlier 20-feature proxy run gave almost exactly the **inverted** answer, which is why this gate must run on the real models
- `fp_scrape_auth_test.R` — the diagnostic behind the FantasyPros intake: proves the auth fence, the parity of scraped vs hand-exported numbers, and records the two dead ends (scripted login, pasted cookies)
- `feature_correlation_diagnostic.R` — read-only correlation report + clustered heatmap per position feature set (consumes in-memory `model_df` + `qb/rb/wr_features` from `01`); flags `findCorrelation` drop candidates but drops nothing

## Domain Conventions

- Fantasy scoring is computed in `01` (`points` column): 6 pts/rush+rec TD, 4 pts/pass TD, 0.1/rush+rec yd, 0.04/pass yd, −2 fumble/INT, `PPR_MULT` per reception. `rush_fbl` is *total* fumbles (all play types), matching the legacy PFR definition.
- Player `Pos` is normalized to each player's most recent position across their whole history (grouped by `player_id`).
- **`player_id` (GSIS) threads through every stage's CSV** and is the unique key for disambiguating players who share a name. Internal joins in `01`/`03` key on it (not name); only the FantasyPros match in `02` stays name-based because FantasyPros provides no id. FantasyPros-only rookies therefore have `player_id = NA`.
- `Floor`/`Ceiling`/`upside_index`/`ceiling_index`/`floor_index` are the **model's own** prediction-interval expectation — deliberately *not* manually adjusted or blended with FantasyPros — while `Final_Projection` is the robust model+expert blend. The bands therefore will *not* necessarily bracket `Final_Projection`; that is by design (they describe the model, and match what `tests/interval_coverage_backtest.R` validates).
- nflverse season summaries arrive pre-aggregated for traded players — no "2TM" handling needed.
- **`points_next_year` is the one numeric column deliberately left NA-bearing.** It is the target, and it is NA wherever the next season does not exist — the `PRED_YEAR` rows, and any player who never played again (a realized **0**, not missing data). `combined`'s blanket `replace_na`/`is.infinite` fills therefore **exclude** it (`across(where(is.numeric) & !any_of("points_next_year"), ...)`), and any future blanket fill must do the same. Filling it with 0 turned every downstream `!is.na(points_next_year)` filter into a no-op — which is why `pred_df` no longer carries that filter — and made the coverage backtest score every band against an actual of 0.
- **All engineered features must be strictly backward-looking** (predicting next-season points, so any feature using current/future-season data leaks). The rolling stats use `rollapplyr(..., align = "right")` and career cumulatives subtract the current season for this reason. `years_since_peak` uses a **trailing** argmax (`running_argmax` helper), not a whole-career `which.max`, which would otherwise recycle the index of a player's peak — including future seasons — into every row.
- Annual maintenance: bump `EVAL_YEAR`, set `SKIP_DATA_LOAD <- FALSE` once to build the new `data/player_stats_final_{START_YEAR}_{EVAL_YEAR}.csv` cache (the path is year-versioned, so a bumped `EVAL_YEAR` will miss the old cache and must be refreshed), re-run the one-time FantasyPros login if the Chrome profile's session has lapsed (the symptom is a warning that a position returned ~10 rows — see the command above `FP_CHROME_PROFILE` in `02`), refresh the manual player-adjustment `case_when` in `02`, and verify positional cutoffs in `03`. The manual CSV exports in `data/fp_raw/{SCORING_TYPE}/` are now only the fallback (steps above `read_fp_projections_csv`), worth refreshing if you want a current safety net.
